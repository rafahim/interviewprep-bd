## Interview prompt

এক মিনিটের মধ্যে relevant background, technical strength এবং role-এর সঙ্গে connection বোঝাও।

## কেন interviewer প্রশ্নটি করেন

এটি শুধু story শোনার প্রশ্ন নয়। Interviewer দেখতে চান তুমি context পরিষ্কার করতে পারো কি না, নিজের responsibility চেনো কি না, action নেওয়ার সময় কীভাবে সিদ্ধান্ত নিয়েছ এবং ফলাফল থেকে কী শিখেছ।

## STAR framework

**S — Situation:** আমি web development-এ কাজ ও শেখার মাধ্যমে frontend, backend এবং deployment-এর end-to-end flow বুঝতে শুরু করেছি।

**T — Task:** কেবল feature বানানো নয়, maintainable এবং user-friendly solution তৈরি করার দক্ষতা দেখাতে চেয়েছি।

**A — Action:** ছোট project-এ UI, API integration, data flow এবং responsive behavior হাতে-কলমে তৈরি করেছি; bug পেলে reproduce করে root cause খুঁজেছি।

**R — Result:** এতে requirements ভেঙে implement করা, trade-off বোঝা এবং কাজের ফল দেখিয়ে ব্যাখ্যা করার অভ্যাস তৈরি হয়েছে।

উপরের উত্তরটি একটি কাঠামোগত নমুনা। এটিকে নিজের বাস্তব অভিজ্ঞতার সঙ্গে মানিয়ে নাও; কোনো ঘটনা না ঘটলে সেটি নিজের জীবনের ঘটনা বলে দাবি না করে কাছাকাছি project example বা hypothetical approach স্পষ্টভাবে বলো। Result-এ পরিমাপযোগ্য evidence থাকলে ব্যবহার করো, কিন্তু সংখ্যা বানিয়ে বলো না।

## Strong answer checklist

- Role-এর সঙ্গে সম্পর্কহীন personal details বাদ দাও।
- নিজেকে একাধিক contradictory seniority label দিও না।
- Claims-এর পেছনে concrete project example রাখো।

## Practice version

নিজের উত্তর 60–120 সেকেন্ডে রেকর্ড করে শুনো। Situation ও Task সংক্ষিপ্ত রাখো; Action অংশে “আমি কী সিদ্ধান্ত নিয়েছিলাম” পরিষ্কার করো; Result-এ কী deliver হয়েছে, কার উপকার হয়েছে এবং পরেরবার কী বদলাবে তা বলো।
